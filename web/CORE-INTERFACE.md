# Workshop core integration surface

The implemented source of truth is `src/pages/workshop/core/types.ts` and the returned controller type in `controller.ts`. All public state snapshots are deeply readonly. The document cache is keyed by API client, authenticated actor and target playlist; tools do not create another draft order or mutation queue.

The controller exposes:

- `subscribe/getSnapshot/load`, immutable `actor/playlistId`, `api/client/operations`, `permission(group,subject?)` and `hasDraft()`.
- `moveOccurrence(key,position1)`, `removeOccurrence(key)`, `appendTracks(tracks,{mode:"append"|"append-missing",origin})` and `replaceDraftOrder(uris,{expectedRevision,expectedLockRevision?,tracks?,discardStaging?})`.
- `getPreviewInput()/applyPreview(input,uris)`, `setLocks(map,expectedLockRevision?)` and `configurationChanged()`. Preview input captures draft/lock revisions, exact URI multiplicity and held indices. A preview must be a full permutation preserving every held index. Manual moves preserve legacy source/destination hold rules; an intervening held row may shift when another row crosses it. Removal is permitted by the independent draft rights.
- `claim({owner,resource,access,reason})->release`, including tracks/metadata resource claims. Permission groups are draft, preview, locks, review, save, history, snapshot, snapshot-read, snapshot-create, snapshot-delete, metadata, collect, routine and pause. A tool adapter holds its own tracks claim until authoritative initial locks are installed; release its own claim and install the confirmed map synchronously without removing another feature's claim.
- `prepareReview()/prepareSnapshotRestore(id)/prepareVisibility(public:boolean)` return frozen discriminated reviewed actions. `submitReviewed(id)/retryExactRequest()/observeReceipt()` share exact request identity and accepted-operation observation. Visibility admission kind is visibility; its reviewed/domain kind is privacy. It patches playlist.public only and preserves independent drafts.
- `checkCurrent()/adoptCurrent(id)/discardLocal()`. Current-state inspection cannot settle an unknown accepted operation or confirm/reset history. Adoption is a distinct explicit action.
- `loadDrafts/saveDraft(name,id?)/deleteDraft(id)/loadNamedDraft(id,allowReplace?)`, `reviewIsCurrent()` and `retainTool(id,initial)` for stable feature state. Tools own their state changes, never a second draft array.

`SourceStagingSnapshot` is the closed readonly raid_promotion / archive_append / archive_restore union. Target identity is the controller identity, never an API URL. `registerSourceCoordinator({snapshot,discard,subscribe})->unregister` copies/freezes snapshots and invalidates stale reviews. Nonempty staging participates in dirty navigation. Source-only staging refuses a target-only save without a finalization coordinator. Discard returns only uncommitted staging and retains saved/uncertain facts.

`workspace.tsx` exports WorkshopTool, WorkshopToolContext, useWorkshop and useWorkshopWorkspace. WorkshopEntry/WorkshopPage accept a readonly registry. ToolId is algorithms, locks, catalog, external, snapshots, details, sources, archive or routines. Empty registries render no tool controls. A nonempty registry renders one Tools button, opening a retained actor/target-scoped chooser. Each exact named entry pushes the corresponding panel; Escape returns to its chooser trigger and then the original Tools button. A registry rowActions(context,occurrence) hook supplies a component in the existing occurrence actions area.

WorkshopToolContext contains controller, openReview(review), resolveDraft(action):Promise<boolean>, openTool(id,trigger,mode?) and fallback. Independent draft or staged work must resolve before snapshot restore: resolveDraft offers Review & save / Discard / Stay. Review opens save and returns false; it never automatically continues the original restore or navigation after a later save. Only an explicit discard resolves true. Tools prepare via authoritative restore-context and then call openReview; they do not submit restores themselves.

Snapshot restore context/version1 includes target/current/action/resources/required_bookkeeping/review_binding. Submission sends only reviewed_scope and reviewed_before_order with the frozen original key. Core derives the endpoint from snapshot ID. Terminal verification checks actual resource.current_track_uris, returned occurrence DTO order and session_history bookkeeping; it never copies the snapshot into an assumed current playlist or invents Workshop batch counts.

Task.scrollKey optionally retains actor-scoped panel scroll. Async navigation decisions must explicitly allow departure for every active blocker. The fixture build includes a two-tool chooser harness.
